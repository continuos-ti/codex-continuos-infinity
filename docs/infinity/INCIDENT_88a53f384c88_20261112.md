## Defeito reproduzido e correção no código de desenvolvimento

Na etapa DEV “Verify runtime”, a interface retornou **“DEV Full harness tunnel credentials are not configured”** apesar de o transporte configurado ser `external-cloudflare`, que explicitamente dispensa credenciais OpenAI Tunnel. O defeito foi localizado em `launcher/electron/runtime.cjs`, método `devDoctor()`: ele exigia `config.tunnel.runtimeKeyFile` de todos os perfis Full e só consultava a saúde se `config.tunnel` existisse.

Correção no worktree (não aplicada ao processo vivo): separação das validações entre transporte `openai-tunnel` e `external-cloudflare`; o segundo exige a configuração explícita do gateway e consulta `readTunnelHealth`, que já implementa a saúde Cloudflare. Testes adicionais cobrem gateway saudável, indisponível e configuração incompleta, sem assumir acesso ao catálogo ou executar ferramentas externas. Os 66 testes `launcher/tests/runtime-host.test.cjs` passaram, sem falhas, e `git diff --check` passou.

Verificação integral adicional: `bun run verify`, código 0; suíte principal com 1.317 aprovados, 113 ignorados, zero falhas em 1.430 testes; launcher com 455 aprovados, quatro ignorados e zero falhas; typecheck, build e smoke relocável aprovados. Os avisos de chunk Vite acima de 500 KB e HTTP 502 do catálogo durante o smoke não alteraram seu resultado, mas não devem ser interpretados como prova de E2E autenticado.

O launcher em execução não foi reiniciado para evitar perturbar tarefas existentes; a correção só terá efeito em versão futura carregada do código atualizado. O conector externo **ContinuosWebIntegracao DEV** não foi autenticado/validado; a lista de plugins observada mostrou o conector de produção, que **não** foi substituído ou reutilizado como DEV. Nenhuma credencial de produção foi copiada.

## Finding adicional: gateway DEV apontava para produção

Uma leitura independente da configuração Cloudflare demonstrou que `codex-native2.continuos.com.br` pertence ao túnel compartilhado `windows-local-mcp` e encaminha para `127.0.0.1:28765`, processo `codex_cf_oauth.py` que importa o dispatcher de produção. Portanto, o perfil DEV Full não estava isolado no plano MCP, apesar do home e browser separados e do health check responder. O conector DEV não deve ser autorizado nem usado nesse endpoint. Não foi feita chamada MCP nem alterado o túnel de produção.

Foi adicionada a validação `validateIsolatedDevExternalGateway`: bloqueia o origin de produção, exige host DEV dedicado e mesmo origin para MCP/health. Setup, `dev status`, `dev chat` e launcher doctor agora falham de forma fechada. A suíte dirigida passou com 97 testes, um ignorado e zero falhas. O perfil existente permanece configurado com o endpoint antigo, mas a nova versão do código o considera não pronto. Provisionamento do túnel, serviço OAuth/MCP e estado DEV próprios permanece pendente.
